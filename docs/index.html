side·piece

The other model, on the side.

Your coding agent is good. It is also the only opinion in the room.

side-piece hands work to a different model — a review, a migration, a second read on the thing you are not sure about — and brings the answer back.

It drives the CLIs already on your machine. Your logins, your subscriptions, your terminal. Runs locally, resumes cleanly, and there is nothing new to sign up for.

Install

From inside your project, give your coding agent this prompt:

Let's install `@tjw.dev/side-piece` in this project, then tell me how to use it

Works in

Claude Code.claude/skills
Codex.agents/skills
opencode.agents/skills

Then ask for a model by name

have opus review this diff adversarially

get a second opinion from sol on the cache invalidation

ask mimo to try the migration in a worktree

Say the short name — opus, sol, mimo — and the skill checks the live catalog and resolves it to whatever that provider actually calls it today. Ask for something that is not there and it tells you, rather than quietly picking something else.

Every delegated run is a background job with a session you can return to. A provider that falls over is resumed, not restarted. A long review outlives a disconnected client. Reviews get their own worktree and no permission to write to yours.

Questions

Which models can it reach?
Whichever CLIs you already have installed and signed in — claude, codex, gemini, opencode. side-piece runs those binaries on your machine, as you, spending the subscriptions you already pay for. Nothing new to sign up for and no API keys to paste.
Does my code go anywhere new?
No. It goes exactly where it already goes when you run those CLIs yourself. side-piece is a router, not a service — there is nothing in between.
What lands in my project?
One skill in .agents/skills/side-piece, a link where Claude Code looks for it, and an ai-cli entry in each client's MCP config. All committed. The only thing in node_modules is the pinned ai-cli-mcp server.
Will it pick a model I did not ask for?
Never. It checks the live catalog before routing, so it cannot invent a name, and naming a model always beats its own preference. Ask for something that is not there and it says so.
Is the version pinned?
To the patch. The server version lives in one package.json and nowhere else, so it cannot drift out from under a config file.
Do I have to use the prompt?
No. npm i -D @tjw.dev/side-piece && npx side-piece install does the same work, and the README shows how to place every file by hand.
